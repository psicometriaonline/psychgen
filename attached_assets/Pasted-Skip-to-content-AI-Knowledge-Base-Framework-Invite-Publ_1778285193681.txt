PsychGen BR — Como funciona e como testar
O que foi entregue
A Tarefa #6 montou um MVP local rodando 100% via Docker no Windows (ou macOS/Linux), com toda a stack persistente e auto-bootável com um único comando.

Arquitetura — 4 contêineres orquestrados
Serviço	O que faz	Porta exposta
postgres	Banco PostgreSQL (volume psychgen_pg_data)	5432
r-engine	API Plumber (R 4.4.3 + mirt + EGAnet + udpipe + AIGENIE)	interna apenas
api	Node 24 / Express — gera scripts R, persiste jobs, faz proxy para o R	8080
web	Nginx servindo o React build + proxy /api/* → api:8080	5173
Volumes nomeados garantem que a biblioteca R compilada (psychgen_r_lib), o cache do udpipe (psychgen_r_cache) e o banco sobrevivem a docker compose down. Só docker compose down -v apaga tudo.

O que rola por baixo do capô
Backend é a fonte da verdade do R: os geradores em artifacts/api-server/src/lib/r-syntax/ montam o script R completo (com MERGE_AND_SOURCE dos stages) a partir dos parâmetros do formulário.
O mesmo texto é enviado pra UI no painel lateral (Monaco com syntax highlighting + botão Baixar .R) e persistido em pipeline_jobs.script_r.
Quando você clica em "Executar", a API faz POST /run/script no r-engine com exatamente esse script. O R executa, escreve PSYCHGEN_PROGRESS/PSYCHGEN_LOG num arquivo NDJSON num volume compartilhado, e a API faz tail desse arquivo e empurra como SSE pra UI em tempo real.
Sem comando manual de migração: o entrypoint do contêiner api roda drizzle-kit push --force automaticamente antes de subir o Node — primeira execução já tem o schema pronto.
Como testar (passo a passo)
Pré-requisitos
Docker Desktop ≥ 4.30 (Windows precisa de WSL 2)
≥ 8 GB de RAM livres pro Docker
≥ 5 GB de disco
1. Subir tudo
git clone <este-repo>
cd <pasta>
cp .env.example .env
# edite .env e ponha sua OPENAI_API_KEY (ou AI_INTEGRATIONS_*)
docker compose up -d --build

⚠️ A primeira build leva 15–30 min porque o r-engine compila mirt, EGAnet, udpipe etc. da fonte. Builds seguintes ficam em cache (segundos).

2. Verificar que está saudável
# Status dos contêineres (todos devem estar "healthy"):
docker compose ps
# Health profundo via API (mostra versão do R + lista de pacotes):
curl 'http://localhost:8080/api/healthz?deep=1' | jq
# R engine direto (interno — entra no container):
docker compose exec r-engine curl -s http://localhost:8000/healthz | jq
# Logs ao vivo:
docker compose logs -f api
docker compose logs -f r-engine

3. Abrir a UI
Abra http://localhost:5173 no navegador.

No Dashboard você deve ver:

Barra de saúde no topo: API/DB/R engine com bolinha verde
Versão do R (R 4.4.3) e modo (http)
Badges de AIGENIE: instalado e udpipe PT-BR: cache OK
Lista expandida com cada pacote R e sua versão (mirt 1.43, EGAnet 2.0.5, etc.)
4. Testar o fluxo "preview = script executado"
Crie um projeto novo (botão Novo Projeto).
Vá pra qualquer estágio — ex: AIGENIE (/projects/:id/aigenie).
Preencha o formulário (construto, número de itens etc.).
No painel lateral à direita o Monaco deve mostrar a sintaxe R com highlighting, atualizando ~350ms depois que você para de digitar.
Clique no botão .R — baixa exatamente o script que vai rodar.
Clique em Executar — o painel de logs abre via SSE e mostra [ETAPA 1/N] ... em tempo real, com barra de progresso.
Quando terminar, o job ficou registrado e seu script_r está persistido — confirme:
docker compose exec postgres psql -U psychgen -d psychgen \
  -c "SELECT id, stage, status, length(script_r) AS chars FROM pipeline_jobs ORDER BY id DESC LIMIT 5;"

5. Repita pros outros estágios
Predição de dificuldade (udpipe + glmnet)
IRT (mirt: Rasch / 2PL / 3PL / graded)
Plano amostral (pós-estratificação + design effect)
Export (gera um .xlsx multi-aba via openxlsx)
6. Teste a persistência (o ponto da história "R compilado uma vez só")
docker compose down            # para tudo
docker compose up -d            # sobe DE NOVO
# Em < 5 segundos tudo volta. NENHUM pacote R reinstala.

Se você fizer docker compose down -v aí sim apaga os volumes e a próxima build leva 15–30 min de novo.

Coisas para conferir / atenção
AIGENIE: o SHA padrão em docker/r-engine/install_packages.R (DEFAULT_AIGENIE_REF = "ff19571...") é um placeholder pinado. Se quando você rodar o build o GitHub responder 404 nesse commit, o instalador faz fallback graceful (loga warning e segue — stage1_aigenie.R cai pra igraph::cluster_louvain). Pra forçar uma SHA real, ponha INSTALL_AIGENIE_REF=<sha> no .env.
Migração para VPS é trivial: mesmo docker-compose.yml, mesmo .env — basta docker compose up -d --build no servidor.
Modo dev fora do Docker (Replit, edição rápida): docker compose up -d postgres e rode a API/web no host (ver seção "Desenvolvimento" do README).
